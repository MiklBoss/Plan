# Опора + Qwest — первая игровая версия

## Что добавлено

- На экране дня: кошелёк, уровень и ближайшая награда; босс дня ослабевает при выполнении задач и подзадач.
- «Моя игра»: персонаж, опыт, уровень, магазин желаний, история начислений и покупок.
- Усилие задачи: 3 / 10 / 25 монет и 15 / 50 / 125 XP. Быстро добавленная и старая задача по умолчанию даёт 10 монет.
- Монеты и XP начисляются при первом завершении. Повторная галочка не даёт повторной награды. Уже заработанное сохраняется при снятии отметки или удалении задачи.
- У основной задачи с подзадачами общий фонд. Размер фиксируется при первом начислении. Подзадача получает долю, завершение основной задачи — остаток. Автоматическое завершение детей не начисляет второй фонд.
- XP не расходуется. Следующий уровень каждые 500 XP. Нет штрафов за пропуски, обычный отдых не требует монет.
- Собственные награды: название, цена в монетах, стоимость в евро. Получение требует подтверждения. Отмена покупки возвращает монеты и расход бюджета.
- Бюджет задаётся отдельно для каждого календарного месяца. Не переносится автоматически. Награда без денежных расходов имеет стоимость 0 евро.
- История хранит цену покупки на тот момент: изменение желания не переписывает прошлые покупки.
- Новый журнал, магазин и бюджет входят в существующий экспорт, импорт, синхронизацию GitHub и объединение вкладок. Старые резервные копии принимаются.

## Как обновить существующую Опору

1. В текущей Опоре откройте настройки и нажмите «Скачать копию». Сохраните JSON с реальными планами отдельно.
2. Откройте в Codex проект существующего репозитория `opora-private`, прикрепите этот архив и поручите перенести игровое обновление в текущий проект, сохранив его последние изменения и данные. Нужны `app.js`, `core.js`, `game.js`, `styles.css`, `sw.js`, `server.mjs` и папка `tests`. Репозиторий может иметь более новые изменения — сначала сравните файлы.
3. Не заменяйте файл реальных данных `opora-data.json`, не удаляйте планы, не очищайте браузерное хранилище. Файл данных намеренно не включён в этот пакет.
4. Запустите `npm test`. Проверьте задачу → начисление → магазин → покупка → экспорт/импорт.
5. После проверки опубликуйте изменения существующим способом GitHub Pages. При ручной загрузке файлы должны быть в корне репозитория, а не во вложенной папке.
6. После публикации закройте старые вкладки приложения на ВСЕХ устройствах и снова откройте страницу. Убедитесь, что появился блок «Моя игра», прежде чем синхронизировать. Старый код не знает новый журнал и способен удалить игровые данные при сохранении или синхронизации.
7. На телефоне откройте «Мои награды», задайте бюджет текущего месяца и добавьте первое желание.

Архив содержит исходники и обновлённый `opora-github-pages.zip` со статическими файлами для публикации. Сам архив не изменяет действующий сайт.

## Важные особенности

- Ранее завершённые задачи автоматически не начисляются, чтобы не менять исходный баланс без вашего выбора. Если снять галочку и снова завершить такую задачу, её первое игровое начисление произойдёт.
- Выбор горячей задачи не увеличивает цену: усилие задаётся отдельно.
- Босс отражает текущий план выбранного дня. Добавление или удаление задач меняет его HP; за босса отдельный денежный бонус не начисляется.
- Перед покупкой синхронизируйте устройства. Одновременные покупки офлайн могут вместе превысить кошелёк или бюджет. Объединение сохраняет все операции и показывает перерасход: отмените лишнюю покупку в истории. Это не банковский кошелёк и приложение не переводит реальные деньги.
- Личная отметка выполнения остаётся источником начисления; система не проверяет, действительно ли задача сделана.
- Obsidian пока остаётся отдельным местом для заметок. Автоматического переноса его опыта и синхронизации с хранилищем Obsidian в этой версии нет.

## Проверки

Прошли 9 автоматических тестов: старые копии, однократное начисление, общий фонд, повторная синхронизация и офлайн-слияние, месячный бюджет, покупка и возврат, обнаружение перерасхода, проверка повреждённых данных, сохранение фонда после удаления родительской задачи, прогресс босса.

Дополнительно проверен сценарий интерфейса через DOM: создать дело → выполнить → задать бюджет → добавить желание → купить → перезапустить → отменить → повторно выполнить → изменить усилие. JavaScript синтаксически проверен.

Полноценная визуальная проверка мобильного и настольного браузера не выполнена: Chromium отсутствует в среде, его загрузка недоступна. Перед публикацией нужна проверка внешнего вида на телефоне.
